## 对客户端设计的影响

### 0. 网页登录实测（2026-10-08 修正版，撤回 10-07 的错误结论）

> 上一轮曾得出"官方 PC 网页端完全没有登录入口"——**该结论错误，已撤回**。
> 错误原因：只扫描了官网营销首页（`/`）的 DOM，就外推"不存在登录能力"。
> 但从首页没有链接 ≠ 路由不存在。以下为直接测试 `/login`、`/hello` 与 OAuth 链路的修正结果。

| 项目 | 实测结果 | 验证方法 |
| --- | --- | --- |
| 登录页面存在 | ✅ YES | 直接访问 `https://www.baicizhan.com/login`，返回完整登录表单（邮箱/密码/记住我/忘记密码） |
| 欢迎页存在 | ✅ YES | 直接访问 `/hello`（"已有账号? 点此登录"） |
| 邮箱登录服务端 | ✅ 在线 | 提交测试账号返回业务错误「无效用户名或密码」（服务端在处理登录请求） |
| 微信登录 | ❌ 官方 OAuth 配置问题 | 官方页面点击微信 → 302 到 open.weixin.qq.com → 微信返回「redirect_uri 参数错误」（**标准浏览器同样复现**，详见 auth-flow.md） |
| 客户端是否修改 OAuth URL | ✅ NO | 同端点在不同 UA 下返回完全相同 URL（仅 state 随机）；全项目搜索无 OAuth 构造/修改代码 |
| 导航白名单 | ✅ 已实现 | AUTH_NAVIGATION_ALLOWLIST（官方域 + OAuth 提供方），单元测试覆盖 |
| Cookie 白名单 | ✅ 独立实现 | 仅 `baicizhan.com` 及子域；第三方 OAuth 域 NEVER 收到百词斩 Cookie |

**对客户端的影响**：登录窗口已直接打开 `/login`；**邮箱登录优先**（服务端可用，待用户真实凭据完成端到端验证）；
微信入口保留但在 UI 中标注当前官方异常。上一轮"登录入口不存在"的文案已全部移除。

### 微信专项测试表（2026-10-08）

| 测试 | 结果 |
| --- | --- |
| Edge/标准浏览器打开官方登录页 | ✅ 正常 |
| Edge/标准浏览器点击微信 | ❌ redirect_uri 参数错误 |
| Tauri 官方登录页 | ✅ 正常 |
| Tauri 点击微信 | ❌ redirect_uri 参数错误（用户实测） |
| Edge OAuth URL | `appid=wx3eaeff9db2a3c4e9&redirect_uri=http%3A%2F%2Fbaicizhan.com%2Fauth%2Fweixin%2Fcallback&response_type=code&scope=snsapi_login&state=<随机>` |
| Tauri OAuth URL | **与 Edge 完全一致**（服务端 302 生成，UA 无关） |
| 两者是否一致 | ✅ 一致 |
| redirect_uri 值 | `http://baicizhan.com/auth/weixin/callback`（http + 裸域） |
| 是否 double encode | ❌ 无（单次编码 `%3A%2F%2F`） |
| 微信二维码/授权页 | ❌ 未到达（微信在校验 redirect_uri 阶段即拒绝） |
| 是否返回百词斩 | ❌ 未发生 |
| SessionProbe 验证 | 待用户完成邮箱登录后实测 |

**根因**：微信开放平台登记的回调域与线上生成值不符（`baicizhan.com` 裸域已 301 到 `www`，且为 http）。
属官方服务端配置问题；客户端不能通过修改 appid/redirect_uri 修复（也不允许这样做）。

### 1. 登录状态无法从 HTML 直接判定

由于主站是 SPA，公开 HTML 在所有状态下几乎相同。因此：

- **HTTP 200 ≠ 已登录**（v0.2.0 已修复：0.1.0 曾用此方式误判）；
- **Cookie 数量 > 0 ≠ 已登录**（未登录也可能有匿名统计 Cookie，已修复）；
- SessionProbe 的策略：携带会话访问官方首页，检查
  1) 是否被重定向到登录入口（`passport.*` / login 路径）；
  2) 响应中是否出现登录后特征（退出登录 / 个人中心 等）；
  3) 响应中是否出现未登录特征（立即登录 / 请先登录 等）。
- 找不到可靠证据时，状态显示为 **「会话待验证」**（`unverified`），
  绝不显示为已登录。这是当前 SPA 结构下的诚实结论。

### 3. 后续研究方向（需要用户配合）

如果希望进一步接入官方数据，可以在**用户本人登录后**做以下研究（属于正常网页流程观察）：

1. 在官方登录窗口中登录后，于官方页面按 `F12` → Network 面板；
2. 观察页面**自身**加载的数据请求（域名、路径、方法、必需 Header）；
3. 将观察结果记录到本文件（**不要包含任何 Cookie/Token 具体值**）；
4. 评估其是否为"官方网站正常网页流程本身使用的数据"——只有满足该条件、
   且不依赖签名/风控绕过时，才允许在 `OfficialWebAdapter` 中实现对应 READ。

**注意**：手机 App 的私有接口（含签名算法）无论是否可复现，均不在本项目的允许范围内。

### 3.5 第三方同步证据（存在性参考，不复制实现）

已知第三方浏览器扩展（如"百词斩助手"）公开宣称可将网页端收藏 / 背词行为同步到手机 App。
本项目将其**仅视为「跨端同步路径技术上可能存在」的存在性证据**：

- 不复制其代码；不复制/猜测其使用的接口；不将其接口视为官方公开 API；
- 如需验证（用户侧黑盒）：电脑端产生一次学习行为 → 检查手机 App 是否出现对应变化；
- 当前结论：`SYNC_PATH_EXISTS = 未验证`（需用户实测）；`OFFICIAL_PUBLIC_API = 未验证`。
  两者是**独立概念**，不可互相推导。
